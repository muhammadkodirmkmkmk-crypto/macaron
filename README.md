# 🌾 Sana Bogatir — аналитика сушки

Telegram-агент фабрики **Sana Bogatir**: читает отчёты о сушке в рабочей группе,
распознаёт номер сушки и показания табло **с фотографии** и собирает всё в живой
дашборд на 31 сушку.

Интерфейс в фирменных цветах — тёмно-синий `#0A273D` и золотой `#FBC443`, логотип
в шапке и на странице входа. Цвета **графиков** при этом остались из проверенной
палитры: они прошли проверку на различимость при дальтонизме, а фирменные оттенки
используются только в «хроме» интерфейса (шапка, кнопки), чтобы золотой не путался
со статусом «запаздывает».

Оператор ничего не меняет в своей привычке. Понимаются три вида сообщений:

```
00:28 kirdi burama                  ← только заложили
00:28 kirgan 10:30 chiqdi burama    ← часы захода и выхода
Burama 9 soat 30 minutda chiqdi     ← длительность
Pautinka 14 soatda chiqdi trewena yuq
```

Про первый: если написали «kirdi» и не написали «chiqdi», бот запоминает загрузку
и **через 10 часов сам напоминает в группу** реплаем на то самое сообщение:

```
⏰ 10 soat bo'ldi
🔥 Sushka №12 · Burama
Kirgan: 30.07 00:28 · o'tdi 10 soat 03 min
Holati qanday? Chiqqan bo'lsa, vaqtini yozing.
```

Как только по этой сушке приходит отчёт о выходе, напоминание снимается само.
Срок меняется в `LOAD_REMINDER_HOURS`.

Бот сам достаёт: продукт → `Burama`, время → `602 мин` (и реальные `00:28 → 10:30`,
с переходом через полночь), номер сушки → `26` (с фото), температуру и влажность →
`81.9° / 18%`, качество → `брак / норма`.

**В личке бот отвечает на свободные вопросы** — по-русски и по-узбекски:

```
— 7-apparat hisoboti
— Qaysi davr uchun hisobot kerak? Bugun, hafta, oy yoki boshqa muddat?
— bir hafta
— 7-sushka hisoboti (7 kun)
  Partiyalar: 6 ta · O'rtacha vaqt: 13 soat 14 min · Brak: 1 ta (16.7%)
  Kunlik: 29.07 — 1 partiya, 14 soat 55 min (Pautinka) …
```

## 1. Что нужно от вас: два ключа

| Что | Где взять | Обязательно |
|---|---|---|
| **`TELEGRAM_BOT_TOKEN`** | Telegram → [@BotFather](https://t.me/BotFather) → `/newbot` | да |
| **`ANTHROPIC_API_KEY`** | [console.anthropic.com](https://console.anthropic.com) → API Keys → Create Key | да, без него не читается номер сушки с фото |
| Аккаунт [Railway](https://railway.com) | вход через GitHub | да, чтобы всё работало 24/7 |
| Аккаунт [GitHub](https://github.com) | | да, туда заливается код |

Больше ничего не нужно. Никаких ключей от Telegram API (`api_id` / `api_hash`) —
мы работаем через обычного бота, а не через ваш личный аккаунт.

**Про деньги.** Railway ≈ $5/мес. Anthropic — оплата по факту: одно фото стоит
примерно $0.003–0.005. При 60 партиях в день это **$6–9 в месяц**.
Если хотите совсем без затрат на распознавание — поставьте `VISION_ENABLED=0`,
тогда бот будет переспрашивать номер сушки в чате.

## 2. Настройка бота в BotFather (3 минуты)

1. `/newbot` → имя, например `Makaron Analytics` → username `makaron_analytics_bot`.
2. Скопируйте токен вида `7612345678:AAF...` — это `TELEGRAM_BOT_TOKEN`.
3. **Обязательно** отключите Privacy Mode, иначе бот не увидит сообщения в группе:
   `/mybots` → выберите бота → *Bot Settings* → *Group Privacy* → **Turn off**.
4. Добавьте бота в группу «Makaron suwka» и сделайте **администратором**
   (достаточно права читать сообщения).
5. Напишите в группе `/id` — бот ответит `Chat ID: -1001234567890`.
   Это значение положите в `ALLOWED_CHAT_IDS`.

## 3. Развёртывание на Railway (10 минут)

```bash
# на вашем компьютере
cd makaron-analytics
git init && git add . && git commit -m "makaron analytics"
gh repo create makaron-analytics --private --source=. --push
# или создайте репозиторий на github.com вручную и запушьте
```

Дальше в браузере:

1. [railway.com](https://railway.com) → **New Project** → *Deploy from GitHub repo* → ваш репозиторий.
2. **Variables** → вставьте переменные (см. `.env.example`):
   ```
   TELEGRAM_BOT_TOKEN=7612345678:AAF...
   ANTHROPIC_API_KEY=sk-ant-api03-...
   ALLOWED_CHAT_IDS=-1001234567890
   DASHBOARD_PASSWORD=любой_пароль
   TZ=Asia/Tashkent
   ```
3. **New** → *Database* → **Add PostgreSQL**. Railway сам подставит `DATABASE_URL`,
   и данные переживут перезапуск. (Без Postgres будет SQLite — работает, но
   база стирается при передеплое.)
4. **Settings** → *Networking* → **Generate Domain**. Получите адрес вида
   `https://makaron-analytics-production.up.railway.app`.
5. Вернитесь в **Variables**, добавьте `PUBLIC_URL=<этот адрес>` — бот начнёт
   подставлять ссылку в отчёты.

Готово. Откройте адрес — увидите дашборд.

## 4. Как это работает

```
Telegram-группа                бот (aiogram)                    дашборд (FastAPI)
  фото + подпись   ──►   1. regex по тексту          ──►   PostgreSQL   ──►   графики
                         2. Claude Vision по фото                             Excel-выгрузка
                         3. не распознал → переспросил
```

**Где работает.** Одинаково в группе и в личке с ботом. В группе бот молчит
(ставит 👌 и пишет только при аномальном времени), чтобы не мешать переписке.
В личке отвечает карточкой — видно, что именно записалось:

```
✅ Yozib oldim
🔥 Sushka №27
🍝 Pero · 10 soat 30 min
🌡 82.4° · 💧 8%
✅ sifat me'yorida
```

Если номер сушки на фото не читается, в личке достаточно прислать следующим
сообщением просто число — реплай не нужен.

**Порядок распознавания**

1. Текст разбирается регулярками мгновенно и бесплатно: продукт, часы, минуты,
   `trewena yuq / bor`. Понимает опечатки (`spral` → `Spiral`), латиницу и кириллицу.
2. Фото уходит в Claude: оттуда берётся номер сушки со стены и три строки с
   красного табло. Если модель не уверена — номер не выдумывается.
3. Если номера так и нет, бот отвечает на сообщение:
   «Sushka raqamini o'qiy olmadim» — оператор отвечает реплаем числом `26`,
   и запись достраивается. Такие записи помечены ⚠ и видны в фильтре
   «Только требующие проверки».

### Ассистент в личке

Всё, что в личке не похоже на отчёт, уходит ассистенту. Он не считает сам — только
выбирает, какой срез запросить из базы, и пересказывает полученные цифры на языке
вопроса (кириллица → русский, латиница → узбекский).

Что умеет: отчёт по любой из 31 сушки с разбивкой по дням и продуктам, сводка по
цеху, рейтинг медленных и быстрых, статистика по продуктам, список конкретных партий,
брак и проблемы, активность операторов — то есть всё, что есть на дашборде.

Если период не назван, сначала спрашивает: «За какой период — сегодня, неделя, месяц?»
и только потом идёт в базу. `/reset` — начать разговор заново.

Доступ к личке ограничивается `ALLOWED_USER_IDS`; остальным бот не отвечает.

**Про сбои API.** Anthropic иногда отвечает `529 Overloaded` — это не ошибка кода,
а временная перегрузка. Все обращения к модели (и ассистент, и распознавание фото)
идут через `app/claude.py`: до четырёх попыток с нарастающей паузой, затем переход
на запасную модель `ASSISTANT_FALLBACK_MODEL`. Ошибки вида `400 invalid request`
не повторяются — они не пройдут и со второго раза. Пока бот ждёт, в чате держится
статус «печатает».

**Команды бота** (работают в группе)

| Команда | Что делает |
|---|---|
| `/stats` | сводка за сегодня |
| `/report` | отчёт за 7 дней: загрузка, брак, самые медленные сушки, кто молчит |
| `/sushka 27` | карточка конкретной сушки за 30 дней |
| `/oxirgi` | последние 10 партий |
| `/dash` | ссылка на дашборд |
| `/reset` | сбросить разговор с ассистентом |
| `/id` | ID чата и ваш ID |

Каждое утро в 8:00 бот сам присылает в группу сводку за неделю
(`DAILY_REPORT_HOUR=-1` — выключить).

## 5. Что на дашборде

Главный вопрос дашборда — **за сколько аппарат заканчивает партию**, поэтому он
стоит первым и объясняется словами, а не только цифрами.

- **Рейтинг «Сколько сушит каждый аппарат»** — все сушки от медленных к быстрым,
  с отклонением от среднего и пунктиром среднего по цеху. Клик по строке —
  история партий.
- **Сетка 31 сушки**, где крупно показано время последней партии, а не номер:
  номер — подпись, время — главное. Бейдж появляется только при выходе за норму.
  Сортировка: по номеру, сначала медленные, сначала быстрые, сначала недавние.
- **KPI сверху**: партий сегодня и за период, среднее время сушки, уровень брака,
  загрузка парка, сушек отчиталось, записей на проверку.
- **Сводка словами** (ниже сетки, перед графиками): «В среднем аппарат заканчивает
  партию за 10 ч 47 мин. Быстрее всех №12 — 8 ч 54 мин. Медленнее всех №7 —
  13 ч 14 мин, на 2 ч 27 мин дольше среднего». Рядом — самая быстрая и самая
  медленная сушка, разброс по цеху и границы нормы.
- **Среднее время по продукту** с разбросом min–max.
- **Партий в день** и **тренд среднего времени** — видно, когда цех начал сушить
  дольше. Пока данных меньше трёх дней, вместо графика из одного столбца честно
  написано, что данных мало.
- **Распределение времени сушки** — гистограмма по часовым интервалам.
- **Часы выгрузки** — когда реально снимают партии.
- **Брак по сушкам**.
- **Тепловая карта продукт × сушка** — где какой продукт сохнет дольше.
- **Топ отклонений** от нормы и **активность операторов**.
- **Таблица всех партий** с поиском, фильтрами и ручной правкой любой записи.
- **Выгрузка в Excel** — 4 листа: партии, сушки, продукты, дни.

Интерфейс на русском, переключатель **UZ** — на узбекский. Есть тёмная тема.

## 7. Настройка под ваш цех

Всё в переменных окружения (`.env.example`):

| Переменная | Смысл |
|---|---|
| `DRYER_COUNT` | сколько сушек (по умолчанию 31) |
| `PRODUCTS` | список продуктов через запятую, если ваш отличается |
| `NORM_MIN_MINUTES` / `NORM_MAX_MINUTES` | норма времени; за её пределами бот пишет ⚠️ в чат |
| `LOAD_REMINDER_HOURS` | через сколько часов после «kirdi» напомнить в группу |
| `LOAD_REMINDER_ENABLED` | `0` — выключить напоминания о загрузках |
| `STALE_HOURS` | через сколько часов молчания сушка считается «молчащей» |
| `DUP_WINDOW_MINUTES` | окно защиты от дублей: один и тот же отчёт из группы и из лички |
| `ALLOWED_USER_IDS` | кому можно писать боту в личку (пусто = всем) |
| `ASSISTANT_ENABLED` / `ASSISTANT_MODEL` | ассистент в личке и его модель |
| `VISION_ENABLED=0` | отключить распознавание фото |
| `PRIVATE_ENABLED=0` | запретить отчёты в личке с ботом |
| `ALLOWED_USER_IDS` | кому можно писать боту в личку; пусто = всем |
| `DAILY_REPORT_HOUR` | час утреннего автоотчёта, `-1` — выключить |

**Про табло.** Три строки контроллера сохраняются «как есть» в поле `display_raw`.
Порядок строк на МПР-49 фиксированный — **ВРЕМЯ / ТЕМПЕРАТУРА / ВЛАЖНОСТЬ**, —
поэтому разбор идёт по позиции, а не по догадкам о том, что похоже на температуру.
Внутри каждой строки значение считается **по цифрам**: модели регулярно теряют
или сдвигают десятичную точку (`8.19` и `564` вместо `81.9` и `56.4`), а формат
жёсткий — время `hh.mm`, температура `XX.X` (проверка 20–130 °C), влажность целое
0–100 %. Эвристика включается только для строк, которые вообще не прочитались.

Если логика разбора поменялась, всю историю можно пересчитать из сырых строк:

```bash
curl -X POST "$PUBLIC_URL/api/remap-display?key=$DASHBOARD_PASSWORD"
```

Операция идемпотентная, возвращает список изменённых записей.

**Какую модель ставить.** Замер на реальных снимках табло (4 фото × 3 прогона,
та же подсказка, что в проде):

| Модель | Номер сушки | Температура | Влажность | Цена за фото | 12 запросов |
|---|---|---|---|---|---|
| **claude-haiku-4-5** | 12/12 | **12/12** | 12/12 | **~$0.0018** | **16 с** |
| claude-sonnet-5 | 12/12 | 12/12 | 12/12 | ~$0.0036 | 36 с |
| claude-fable-5 | 12/12 | 12/12 | 12/12 | — | 65 с |
| claude-sonnet-4-5 | 12/12 | 9/12 | 12/12 | ~$0.0054 | 34 с |

Номер сушки — главное поле — читают одинаково все. Единственная модель,
ошибавшаяся на цифрах табло, — самая дорогая из проверенных (`sonnet-4-5`
читала `87.9` вместо `81.9`). Haiku при этом вдвое быстрее и втрое дешевле,
поэтому стоит по умолчанию. Выборка маленькая (4 фото × 3 прогона) — если
накопится брак в распознавании, замер стоит повторить на новых снимках.
Если у вас порядок другой — скажите, поправлю за пять минут; сырые данные
никуда не теряются, всё пересчитается задним числом.

## 8. Состав проекта

```
app/config.py      настройки из переменных окружения
app/db.py          схема: batches, raw_messages, pending, dryer_meta
app/parser.py      regex по узбекскому тексту + Claude Vision по фото
app/bot.py         хендлеры Telegram, команды, уточнение номера реплаем
app/analytics.py   все расчёты для дашборда
app/reports.py     текстовые сводки для чата
app/web.py         REST API, авторизация, выгрузка в Excel
app/assistant.py   ассистент в личке: инструменты по базе + Claude
app/claude.py      общий вызов Claude с повторами и запасной моделью
app/main.py        точка входа: бот и веб в одном процессе
static/logo.png    логотип (шапка, страница входа, favicon)
static/dashboard.html   дашборд целиком (без CDN и внешних зависимостей)
seed_demo.py       демо-данные
```

Каждое сырое сообщение сохраняется в `raw_messages` — если понадобится изменить
логику разбора, всю историю можно пересчитать, ничего не потеряв.
