# 🍝 Makaron Analytics

Telegram-агент, который читает отчёты о сушке в рабочей группе, распознаёт номер сушки
и показания табло **с фотографии**, и собирает всё в живой дашборд на 31 сушку.

Оператор ничего не меняет в своей привычке. Пишет как писал:

```
Burama 9 soat 30 minutda chiqdi     [фото сушки №26]
Pautinka 14 soatda chiqdi trewena yuq
```

Бот сам достаёт: продукт → `Burama`, время → `570 мин`, номер сушки → `26` (с фото),
температуру и влажность → `81.9° / 18%`, качество → `брак / норма`.

---

## 1. Что нужно от вас: два ключа

| Что | Где взять | Обязательно |
|---|---|---|
| **`TELEGRAM_BOT_TOKEN`** | Telegram → [@BotFather](https://t.me/BotFather) → `/newbot` | да |
| **`ANTHROPIC_API_KEY`** | [console.anthropic.com](https://console.anthropic.com) → API Keys → Create Key | да, без него не читается номер сушки с фото |
| Аккаунт [Railway](https://railway.com) | вход через GitHub | да, чтобы всё работало 24/7 |
| Аккаунт [GitHub](https://github.com) | | да, туда заливается код |

Больше ничего не нужно. Никаких ключей от Telegram API (`api_id` / `api_hash`) —
мы работаем через обычного бота, а не через ваш личный аккаунт.

**Про деньги.** Railway ≈ $5/мес. Anthropic — оплата по факту: одно фото стоит
примерно $0.003–0.005. При 60 партиях в день это **$6–9 в месяц**.
Если хотите совсем без затрат на распознавание — поставьте `VISION_ENABLED=0`,
тогда бот будет переспрашивать номер сушки в чате.

## 2. Настройка бота в BotFather (3 минуты)

1. `/newbot` → имя, например `Makaron Analytics` → username `makaron_analytics_bot`.
2. Скопируйте токен вида `7612345678:AAF...` — это `TELEGRAM_BOT_TOKEN`.
3. **Обязательно** отключите Privacy Mode, иначе бот не увидит сообщения в группе:
   `/mybots` → выберите бота → *Bot Settings* → *Group Privacy* → **Turn off**.
4. Добавьте бота в группу «Makaron suwka» и сделайте **администратором**
   (достаточно права читать сообщения).
5. Напишите в группе `/id` — бот ответит `Chat ID: -1001234567890`.
   Это значение положите в `ALLOWED_CHAT_IDS`.

## 3. Развёртывание на Railway (10 минут)

```bash
# на вашем компьютере
cd makaron-analytics
git init && git add . && git commit -m "makaron analytics"
gh repo create makaron-analytics --private --source=. --push
# или создайте репозиторий на github.com вручную и запушьте
```

Дальше в браузере:

1. [railway.com](https://railway.com) → **New Project** → *Deploy from GitHub repo* → ваш репозиторий.
2. **Variables** → вставьте переменные (см. `.env.example`):
   ```
   TELEGRAM_BOT_TOKEN=7612345678:AAF...
   ANTHROPIC_API_KEY=sk-ant-api03-...
   ALLOWED_CHAT_IDS=-1001234567890
   DASHBOARD_PASSWORD=любой_пароль
   TZ=Asia/Tashkent
   ```
3. **New** → *Database* → **Add PostgreSQL**. Railway сам подставит `DATABASE_URL`,
   и данные переживут перезапуск. (Без Postgres будет SQLite — работает, но
   база стирается при передеплое.)
4. **Settings** → *Networking* → **Generate Domain**. Получите адрес вида
   `https://makaron-analytics-production.up.railway.app`.
5. Вернитесь в **Variables**, добавьте `PUBLIC_URL=<этот адрес>` — бот начнёт
   подставлять ссылку в отчёты.

Готово. Откройте адрес — увидите дашборд.

## 4. Как это работает

```
Telegram-группа                бот (aiogram)                    дашборд (FastAPI)
  фото + подпись   ──►   1. regex по тексту          ──►   PostgreSQL   ──►   графики
                         2. Claude Vision по фото                             Excel-выгрузка
                         3. не распознал → переспросил
```

**Порядок распознавания**

1. Текст разбирается регулярками мгновенно и бесплатно: продукт, часы, минуты,
   `trewena yuq / bor`. Понимает опечатки (`spral` → `Spiral`), латиницу и кириллицу.
2. Фото уходит в Claude: оттуда берётся номер сушки со стены и три строки с
   красного табло. Если модель не уверена — номер не выдумывается.
3. Если номера так и нет, бот отвечает на сообщение:
   «Sushka raqamini o'qiy olmadim» — оператор отвечает реплаем числом `26`,
   и запись достраивается. Такие записи помечены ⚠ и видны в фильтре
   «Только требующие проверки».

**Команды бота** (работают в группе)

| Команда | Что делает |
|---|---|
| `/stats` | сводка за сегодня |
| `/report` | отчёт за 7 дней: загрузка, брак, самые медленные сушки, кто молчит |
| `/sushka 27` | карточка конкретной сушки за 30 дней |
| `/oxirgi` | последние 10 партий |
| `/dash` | ссылка на дашборд |
| `/id` | ID чата (нужен один раз при настройке) |

Каждое утро в 8:00 бот сам присылает в группу сводку за неделю
(`DAILY_REPORT_HOUR=-1` — выключить).

## 5. Что на дашборде

- **6 KPI**: партий сегодня, среднее время сушки, уровень брака, загрузка парка,
  сушек в работе, записей на проверку.
- **Сетка 31 сушки** — статус, текущий продукт, среднее время, последние показания
  табло. Клик по карточке — история партий этой сушки.
- **Среднее время по продукту** с разбросом min–max.
- **Партий в день** и **тренд среднего времени** — видно, когда цех начал сушить дольше.
- **Распределение времени сушки** — гистограмма по часовым интервалам.
- **Среднее по каждой сушке** с пунктиром общего среднего — сразу видно
  отстающее оборудование.
- **Часы выгрузки** — когда реально снимают партии.
- **Брак по сушкам**.
- **Тепловая карта продукт × сушка** — где какой продукт сохнет дольше.
- **Топ отклонений** от нормы и **активность операторов**.
- **Таблица всех партий** с поиском, фильтрами и ручной правкой любой записи.
- **Выгрузка в Excel** — 4 листа: партии, сушки, продукты, дни.

Интерфейс на русском, переключатель **UZ** — на узбекский. Есть тёмная тема.

## 7. Настройка под ваш цех

Всё в переменных окружения (`.env.example`):

| Переменная | Смысл |
|---|---|
| `DRYER_COUNT` | сколько сушек (по умолчанию 31) |
| `PRODUCTS` | список продуктов через запятую, если ваш отличается |
| `NORM_MIN_MINUTES` / `NORM_MAX_MINUTES` | норма времени; за её пределами бот пишет ⚠️ в чат |
| `STALE_HOURS` | через сколько часов молчания сушка считается «молчащей» |
| `VISION_ENABLED=0` | отключить распознавание фото |
| `DAILY_REPORT_HOUR` | час утреннего автоотчёта, `-1` — выключить |

**Про табло.** Три строки контроллера сохраняются «как есть» в поле `display_raw`,
а разбор по смыслу (`таймер / температура / влажность`) — эвристика:
число с десятичной точкой считается температурой, целое — влажностью.
Если у вас порядок другой — скажите, поправлю за пять минут; сырые данные
никуда не теряются, всё пересчитается задним числом.

## 8. Состав проекта

```
app/config.py      настройки из переменных окружения
app/db.py          схема: batches, raw_messages, pending, dryer_meta
app/parser.py      regex по узбекскому тексту + Claude Vision по фото
app/bot.py         хендлеры Telegram, команды, уточнение номера реплаем
app/analytics.py   все расчёты для дашборда
app/reports.py     текстовые сводки для чата
app/web.py         REST API, авторизация, выгрузка в Excel
app/main.py        точка входа: бот и веб в одном процессе
static/dashboard.html   дашборд целиком (без CDN и внешних зависимостей)
seed_demo.py       демо-данные
```

Каждое сырое сообщение сохраняется в `raw_messages` — если понадобится изменить
логику разбора, всю историю можно пересчитать, ничего не потеряв.
